1. What Is a Rule Set?

A Rule Set is a JSON document you send to the transformer alongside an EDI file. It tells the engine which EDI fields to extract and what names to give them in the output. Rules are applied at runtime — there is no Java code to write and no deployment required.

FieldPurposeRequired?
outputFormatBUSINESS_JSON or FLAT_FILENo (defaults to BUSINESS_JSON)
rulesArray of mapping instructionsYes
flatFileConfigDelimiter and record layoutOnly when outputFormat = FLAT_FILE
{
  "outputFormat": "BUSINESS_JSON",
  "rules": [
    { "type": "SEGMENT_FIELD", "segment": "BEG", "position": 3, "field": "poNumber" },
    ...
  ]
}
Key principle: The output shape is entirely defined by the rules you write. You decide the field names and nesting. The engine follows your instructions.

2. The Two-Step Workflow

1Parse the EDI file first

Send the file to POST /api/edi/parse. The response shows every segment, every element position, and the complete loop hierarchy. This is your design canvas.

2Write rules based on what you see

Find the value in the parse output. Note its segment tag, element position, and which loop it sits in. Write the rule using those exact values.

Important: Element position numbers vary between trading partners. Always parse the actual file you received and read positions from its parse output — never assume from EDI specs alone.

3. Understanding the Parse Output

The parse output is a tree. Every node is either a SEGMENT or a LOOP.

3.1 SEGMENT node

{
  "nodeType": "SEGMENT",
  "tag": "BEG",
  "elements": [
    { "position": 1, "value": "00" },
    { "position": 2, "value": "SA" },
    { "position": 3, "value": "1234"      },  ← position 3 = PO number
    { "position": 4, "value": ""          },
    { "position": 5, "value": "20260304"  }   ← position 5 = PO date
  ]
}

3.2 LOOP node

{
  "nodeType": "LOOP",
  "loopId": "1000",
  "triggerSegment": "N1",     ← first segment tag of this loop
  "occurrence": 1,
  "children": [
    { "nodeType": "SEGMENT", "tag": "N1", "elements": [
        { "position": 1, "value": "ST"                    },  ← qualifier
        { "position": 2, "value": "Virginia Distribution" }   ← name
    ]},
    { "nodeType": "SEGMENT", "tag": "N3", "elements": [...]},
    { "nodeType": "SEGMENT", "tag": "N4", "elements": [...]}
  ]
}

3.3 The five structural patterns

What you see in parse outputRule type to use
A SEGMENT directly under the transactionSEGMENT_FIELD
Same segment tag appears multiple times with different qualifiers (e.g. two DTM with 001 / 002)SEGMENT_FIELD_QUALIFIED
A LOOP appearing a few times with different qualifiers (e.g. N1 loops: ST, BT, VN)LOOP_FIELD
A LOOP that repeats for every line item (e.g. PO1 × 3)LOOP_ARRAY
Data inside a loop that is itself nested inside another loop (e.g. N1 inside HL[S])LOOP_FIELD_NESTED
Line items nested deep inside a loop hierarchy (e.g. HL[I] items inside HL[S])LOOP_ARRAY_NESTED

4. Rule Types Reference

4a. SEGMENT_FIELD

Extracts one element from a segment that is a direct child of the transaction. Gets the first occurrence of that segment tag.

FieldRequiredDescriptionExample
typeYesAlways "SEGMENT_FIELD"
segmentYesSegment tag"BEG"
positionYes1-based element position3
fieldYesOutput field name. Dot notation creates nested objects."poNumber"
{ "type": "SEGMENT_FIELD", "segment": "BEG", "position": 3, "field": "poNumber" }
{ "type": "SEGMENT_FIELD", "segment": "BSN", "position": 2, "field": "shipmentId" }

4b. SEGMENT_FIELD_QUALIFIED

Like SEGMENT_FIELD but scans all occurrences of the segment and picks the one whose element at filterPosition matches filterValue. Essential for segments like DTM and REF that repeat with different qualifier codes.

FieldRequiredDescriptionExample
typeYesAlways "SEGMENT_FIELD_QUALIFIED"
segmentYesSegment tag to scan"DTM"
filterPositionYesPosition of the qualifier element1
filterValueYesQualifier value to match"002"
positionYesPosition of the data element to extract2
fieldYesOutput field name"deliveryDate"
// Two DTM segments with different qualifiers
{ "type": "SEGMENT_FIELD_QUALIFIED", "segment": "DTM",
  "filterPosition": 1, "filterValue": "001", "position": 2, "field": "cancelDate" }

{ "type": "SEGMENT_FIELD_QUALIFIED", "segment": "DTM",
  "filterPosition": 1, "filterValue": "002", "position": 2, "field": "deliveryDate" }

4c. LOOP_FIELD

Finds a specific loop occurrence at the transaction level and extracts one element from a segment inside it. Use a filter to pick the right occurrence when the same loop type appears multiple times (e.g. N1 with ST / BT / VN qualifiers).

FieldRequiredDescriptionExample
typeYesAlways "LOOP_FIELD"
loopTriggerYesTrigger segment tag of the loop"N1", "HL"
filterSegmentNoSegment inside the loop to filter on"N1"
filterPositionNoElement position to compare1
filterValueNoExpected value (qualifier code)"ST"
segmentYesSegment inside the loop to read"N3"
positionYesElement position to extract1
fieldYesOutput field name"shipTo.street"
// Ship-to name from N1 loop where N101 = "ST"
{ "type": "LOOP_FIELD", "loopTrigger": "N1",
  "filterSegment": "N1", "filterPosition": 1, "filterValue": "ST",
  "segment": "N1", "position": 2, "field": "shipTo.name" }

// PO number from HL[O] loop (856 flat structure — HL[O] is at transaction level)
{ "type": "LOOP_FIELD", "loopTrigger": "HL",
  "filterSegment": "HL", "filterPosition": 3, "filterValue": "O",
  "segment": "PRF", "position": 1, "field": "purchaseOrderNumber" }

4d. LOOP_ARRAY UPDATED

Maps every occurrence of a repeating loop into an array of objects. Now supports an optional filter to include only loops matching a qualifier — critical for 856 where all HL levels share the same trigger tag.

FieldRequiredDescriptionExample
typeYesAlways "LOOP_ARRAY"
loopTriggerYesTrigger segment tag of the repeating loop"PO1", "HL"
filterSegmentNoSegment to filter loops on (for 856: "HL")"HL"
filterPositionNoElement position for filter3
filterValueNoOnly include loops where this value matches"I"
arrayFieldYesOutput array field name"lineItems"
itemRulesYesField mappings applied to each loop occurrenceSee below
// 850 line items — all PO1 loops (no filter needed, PO1 is unique)
{ "type": "LOOP_ARRAY", "loopTrigger": "PO1", "arrayField": "lineItems",
  "itemRules": [
    { "segment": "PO1", "position": 2, "field": "quantityOrdered" },
    { "segment": "PO1", "position": 4, "field": "unitPrice" },
    { "segment": "PID", "position": 5, "field": "productDescription" }
  ]
}

// 856 item-level lines — filter to HL[I] only (HL[S/O/T/P] also exist as siblings)
{ "type": "LOOP_ARRAY", "loopTrigger": "HL",
  "filterSegment": "HL", "filterPosition": 3, "filterValue": "I",
  "arrayField": "lineItems",
  "itemRules": [
    { "segment": "LIN", "position": 3, "field": "vendorItemNumber" },
    { "segment": "SN1", "position": 2, "field": "shippedQuantity" },
    { "segment": "PID", "position": 5, "field": "productDescription" }
  ]
}

4e. LOOP_FIELD_NESTED NEW

Navigate a chain of nested loops to reach a deeply nested loop, then extract one element from a segment inside it. Use this when the data you want is inside a loop that is itself inside another loop.

Each step in loopChain navigates one level deeper. The chain is described using LoopChainEntry objects.

LoopChainEntry fields

FieldRequiredDescriptionExample
triggerYesTrigger segment tag of the loop to enter"HL", "N1"
filterSegmentNoSegment to filter on. Defaults to trigger if null."HL"
filterPositionNoElement position. Defaults to 1 if null.3
filterValueNoValue to match. Null = take first matching loop."S"

LOOP_FIELD_NESTED rule fields

FieldRequiredDescriptionExample
typeYesAlways "LOOP_FIELD_NESTED"
loopChainYesNavigation path — array of LoopChainEntrySee below
segmentYesSegment inside the final loop to read"N1"
positionYesElement position to extract2
fieldYesOutput field name (dot notation supported)"shipTo.name"
filterPositionNoQualifier position for segment-level lookup (like SEGMENT_FIELD_QUALIFIED but inside the target loop)1
filterValueNoQualifier value to match on the segment"BM"
// N1[ST] party inside HL[S]: navigate tx → HL[S] → N1[ST], then read N1[pos2]
{ "type": "LOOP_FIELD_NESTED",
  "loopChain": [
    { "trigger": "HL", "filterPosition": 3, "filterValue": "S" },
    { "trigger": "N1", "filterPosition": 1, "filterValue": "ST" }
  ],
  "segment": "N1", "position": 2, "field": "shipTo.name"
}

// REF*BM inside HL[S]: navigate to HL[S], then find REF where REF[1]="BM"
{ "type": "LOOP_FIELD_NESTED",
  "loopChain": [{ "trigger": "HL", "filterPosition": 3, "filterValue": "S" }],
  "segment": "REF", "filterPosition": 1, "filterValue": "BM",
  "position": 2, "field": "billOfLading"
}

// N1 street address: navigate to HL[S] → N1[SF], then read N3[pos1]
{ "type": "LOOP_FIELD_NESTED",
  "loopChain": [
    { "trigger": "HL", "filterPosition": 3, "filterValue": "S" },
    { "trigger": "N1", "filterPosition": 1, "filterValue": "SF" }
  ],
  "segment": "N3", "position": 1, "field": "shipFrom.street"
}

4f. LOOP_ARRAY_NESTED NEW

Navigate a chain of nested loops to reach a parent loop, then map every child loop into an array. Use when line items are physically nested several levels deep.

FieldRequiredDescriptionExample
typeYesAlways "LOOP_ARRAY_NESTED"
loopChainYesNavigation path to the parent of the array loopsSee below
loopTriggerYesTrigger segment of the child loops to iterate"HL"
filterPositionNoPosition to filter child loops3
filterValueNoOnly include child loops matching this value"I"
arrayFieldYesOutput array field name"lineItems"
itemRulesYesField mappings for each array itemSee below
// Items nested inside HL[S] → HL[O] → HL[T] → HL[P], then iterate HL[I] children
{
  "type": "LOOP_ARRAY_NESTED",
  "loopChain": [
    { "trigger": "HL", "filterPosition": 3, "filterValue": "S" },
    { "trigger": "HL", "filterPosition": 3, "filterValue": "O" },
    { "trigger": "HL", "filterPosition": 3, "filterValue": "T" },
    { "trigger": "HL", "filterPosition": 3, "filterValue": "P" }
  ],
  "loopTrigger": "HL", "filterPosition": 3, "filterValue": "I",
  "arrayField": "lineItems",
  "itemRules": [
    { "segment": "LIN", "position": 3, "field": "vendorItemNumber" },
    { "segment": "SN1", "position": 2, "field": "shippedQuantity"  }
  ]
}
When to use LOOP_ARRAY_NESTED vs LOOP_ARRAY: If the HL loops are flat siblings (all at transaction level), use plain LOOP_ARRAY with a filter. Only use LOOP_ARRAY_NESTED when the item loops are physically nested inside a parent loop in the parse output tree.

5. How to Read Element Positions

Elements are numbered 1-based from left to right. BEG03 = segment BEG, position 3.

Parse output:
───────────────────────────────────────────────────────────────────────
"tag": "PO1",
"elements": [
  { "position": 1,  "value": "1"           },  ← PO101: line number
  { "position": 2,  "value": "1080"        },  ← PO102: qty ordered     ← position = 2
  { "position": 3,  "value": "EA"          },  ← PO103: unit of measure
  { "position": 4,  "value": "13"          },  ← PO104: unit price      ← position = 4
  { "position": 5,  "value": ""            },  ← PO105: (empty)
  { "position": 6,  "value": "SK"          },  ← PO106: qualifier
  { "position": 7,  "value": "2713824"     },  ← PO107: SKU number      ← position = 7
  { "position": 8,  "value": "VP"          },  ← PO108: qualifier
  { "position": 9,  "value": "HM9005"      },  ← PO109: vendor part #   ← position = 9
  { "position": 10, "value": "UP"          },  ← PO110: qualifier
  { "position": 11, "value": "850062021402"}   ← PO111: UPC code        ← position = 11
]

Rules you write:
───────────────────────────────────────────────────────────────────────
{ "segment": "PO1", "position": 2,  "field": "quantityOrdered" }
{ "segment": "PO1", "position": 4,  "field": "unitPrice"       }
{ "segment": "PO1", "position": 7,  "field": "skuNumber"       }
{ "segment": "PO1", "position": 9,  "field": "vendorPartNumber"}
{ "segment": "PO1", "position": 11, "field": "upcCode"         }

5.1 Dot notation for nested fields

Rule:    { "field": "shipTo.address.city" }
Output:  { "shipTo": { "address": { "city": "ASHLAND" } } }

6. Designing Rules — Step by Step

1Parse: POST /api/edi/parse with the EDI file

2Find the value you want in transaction.children

3Identify the pattern using this decision flowchart:

Is the value in...

  ┌─ A SEGMENT directly under transaction?
  │     └─ Does the same tag appear multiple times with different qualifiers?
  │           Yes → SEGMENT_FIELD_QUALIFIED
  │           No  → SEGMENT_FIELD
  │
  └─ Inside a LOOP?
        └─ Is that loop a direct child of the transaction?
              Yes → Is the loop a party loop (N1)?     → LOOP_FIELD
                    Is it a repeating line-item loop?   → LOOP_ARRAY  (add filter if needed)
              No  → The loop is nested inside another loop
                    Want one value?    → LOOP_FIELD_NESTED  (with loopChain)
                    Want an array?     → LOOP_ARRAY_NESTED  (with loopChain)

4Note the segment tag, element position, trigger, and any qualifier values

5Write the rule using those exact values

7. Understanding Loop Structure: Flat vs Nested

This is the most important concept when working with 856 (ASN) documents.

7.1 Flat Loop Structure (850, 810)

In 850 and 810, all loops are direct children of the transaction. N1 party loops and PO1 line-item loops sit at the same level.

transaction.children:
  SEGMENT  BEG, CUR, REF, DTM ...      ← direct transaction segments
  LOOP  N1[ST]  (ship-to party)        ← direct child
  LOOP  N1[BT]  (bill-to party)        ← direct child
  LOOP  PO1     (line 1)               ← direct child
  LOOP  PO1     (line 2)               ← direct child

→ Use SEGMENT_FIELD, LOOP_FIELD, LOOP_ARRAY

7.2 Nested Loop Structure (856 N1 inside HL)

In 856, N1 party loops are nested inside the HL[S] (Shipment) loop. They are not direct children of the transaction.

transaction.children:
  SEGMENT  BSN                         ← direct transaction segment
  LOOP  HL[S]  (shipment level)        ← direct child
    ├── SEGMENT  TD1, TD5, TD3, REF, DTM, FOB
    ├── LOOP  N1[SF]  (ship-from)      ← NESTED inside HL[S]
    └── LOOP  N1[ST]  (ship-to)        ← NESTED inside HL[S]
  LOOP  HL[O]  (order level)           ← direct child (FLAT sibling of HL[S])
  LOOP  HL[T]  (tare/pallet level)     ← direct child (FLAT sibling)
  LOOP  HL[P]  (pack/carton level)     ← direct child (FLAT sibling)
  LOOP  HL[I]  (item level)            ← direct child (FLAT sibling)
Key insight for 856: The different HL levels (S, O, T, P, I) are flat siblings at the transaction level — they are NOT physically nested inside each other even though they have a logical parent-child relationship via HL02. Only N1 (and other sub-loops) are physically nested inside HL[S].
Data in 856Location in parse treeRule to use
BSN (shipment ID, date)Direct transaction segmentSEGMENT_FIELD
TD1, REF, DTM inside HL[S]Inside HL[S] — use chain of 1 stepLOOP_FIELD_NESTED
REF*BM inside HL[S] (multiple REF)Inside HL[S] with qualifier filterLOOP_FIELD_NESTED + filterValue
N1[ST] and N1[SF] partiesNested inside HL[S] → N1 loopLOOP_FIELD_NESTED (2-step chain)
PRF order number (in HL[O])HL[O] is a flat sibling → direct from txLOOP_FIELD with filterValue="O"
LIN/SN1/PID item data (in HL[I])HL[I] is a flat sibling → direct from txLOOP_ARRAY with filterValue="I"

11. Common Mistakes

MistakeSymptomFix
Wrong position number Field is empty or has wrong value Parse the actual file and read positions from the parse output. Never assume from EDI specs.
Using SEGMENT_FIELD for a repeated segment Always gets the first DTM/REF, misses the second Use SEGMENT_FIELD_QUALIFIED with the qualifier value.
Wrong loopTrigger Loop not found, field stays empty loopTrigger must match the triggerSegment in the parse output (e.g. "N1" not "1000").
Missing filter on N1 loop Always gets first N1 (ship-to) even when you want vendor Add filterSegment + filterPosition + filterValue to narrow the loop.
Using LOOP_FIELD for data inside HL[S] N1 party data not found N1 is nested inside HL[S] in 856. Use LOOP_FIELD_NESTED with loopChain.
Using LOOP_FIELD_NESTED for HL[O] / HL[I] data purchaseOrderNumber or lineItems missing HL[O] and HL[I] are flat siblings in the schema. Use plain LOOP_FIELD or LOOP_ARRAY with a filter.
LOOP_ARRAY without filter in 856 Array contains unexpected items from HL[S], HL[O], HL[T] loops Add filterSegment="HL" filterPosition=3 filterValue="I" to only include item-level loops.
Schema not loaded (loopsResolved = false) No loops — all segments are flat, LOOP_FIELD returns nothing Check GET /api/edi/schemas. Ensure the schema for the version/transaction is registered.

12. Quick Reference Card

All Rule Types

Rule TypeRequired FieldsUse When
SEGMENT_FIELD type, segment, position, field Segment is a direct child of the transaction (first occurrence)
SEGMENT_FIELD_QUALIFIED type, segment, filterPosition, filterValue, position, field Same segment repeats with different qualifier codes (DTM, REF)
LOOP_FIELD type, loopTrigger, segment, position, field
+ optional: filterSegment, filterPosition, filterValue		 Loop is a direct child of the transaction; want one specific occurrence
LOOP_ARRAY type, loopTrigger, arrayField, itemRules[]
+ optional: filterSegment, filterPosition, filterValue		 Loop repeats for every line item; want all occurrences as an array
LOOP_FIELD_NESTED type, loopChain[], segment, position, field
+ optional: filterPosition, filterValue (for qualified segment)		 Data is inside a loop that is nested inside another loop (e.g. N1 inside HL[S])
LOOP_ARRAY_NESTED type, loopChain[], loopTrigger, arrayField, itemRules[]
+ optional: filterPosition, filterValue		 Line items are physically nested several levels deep in the hierarchy

LoopChainEntry fields (used in LOOP_FIELD_NESTED and LOOP_ARRAY_NESTED)

FieldDefault if nullDescription
trigger—Trigger segment tag of the loop to enter (required)
filterSegmentSame as triggerSegment to filter on inside the loop
filterPosition1Element position for the filter
filterValuenull = first matchExpected value; null means take the first matching loop
